**ຄົບທຸກໜ້າທີ່ · 44 ໜ້າຈໍ · 15 ກຸ່ມ · ພາສາລາວ**
ສ້າງດ້ວຍ HTML/CSS/JS ລ້ວນໆ — ບໍ່ຕ້ອງຕິດຕັ້ງ, ບໍ່ຕ້ອງມີ server, ເປີດໃນ browser ໄດ້ເລີຍ.

> ພະນັກງານຂັບປະຈຳຂອງບໍລິສັດໃຊ້**ລະບົບຄົນລະຊຸດທີ່ບໍລິສັດຕັ້ງບັນຊີໃຫ້** —
> ຈຶ່ງບໍ່ມີໜ້າ ກວດລົດກ່ອນເລີ່ມກະ / ຕາຕະລາງກະ / ຂໍລາພັກ / ຮອບຈ່າຍເງິນເດືອນ / ນຳສົ່ງເງິນສົດ ໃນນີ້.

## ຊຸດ UI — ແດງ & ຂາວ ☀

ແອັບທັງໝົດ (ລວມທັງ shell ນຳສະເໜີ) ໃຊ້ຊຸດ **ແດງ & ຂາວ**:

1. **ຕົງກັບແບຣນ Insee** — ແດງ `#e1252b` ເປັນສີນຳ ພື້ນຂາວສະອາດ
2. **ອ່ານງ່າຍກາງແດດ** — ຄົນຂັບຂັບກາງເວັນເປັນຫຼັກ ພື້ນຂາວສະຫວ່າງກວ່າໃນລົດ
3. **ຊຸດດຽວກັບແອັບລູກຄ້າ** — ສອງແອັບເບິ່ງເປັນຄອບຄົວດຽວກັນ

### ວິທີເຮັດ

- **ບໍ່ໄດ້ຂຽນ CSS 1,700 ແຖວຄືນ** — ເພີ່ມຊັ້ນ override ຢູ່ທ້າຍໄຟລ໌ (377 ກົດເກນ `.scr …`)
  ຊຶ່ງມີ specificity ສູງກວ່າ ແລະ ມາທີຫຼັງ ຈຶ່ງທັບຄ່າເດີມທັງໝົດ

## ເງິນໄປໃສ 💰 (ກົດສຳຄັນ)

ຮູບແບບ **0% ຄ່າທຳນຽມ** — ບໍລິສັດ**ບໍ່ໄດ້ຈັບເງິນຄ່າໂດຍສານ**ຂອງຄົນຂັບເລີຍ

| ລູກຄ້າຈ່າຍແບບ | ເງິນເຂົ້າໃສ | ຜ່ານລະບົບບໍ | ຕ້ອງຖອນບໍ |
|---|---|---|---|
| **ເງິນສົດ** | ມືຄົນຂັບ | ❌ ບໍ່ຜ່ານ | — |
| **QR ບັນຊີຄົນຂັບ** | ບັນຊີທະນາຄານ**ຂອງຄົນຂັບເອງ** ໂດຍກົງ | ❌ ບໍ່ຜ່ານ | ບໍ່ຕ້ອງ |
| **ກະເປົາເງິນໃນແອັບ** | ກະເປົາໃນແອັບ | ✅ **ຜ່ານ** | ຖອນເຂົ້າບັນຊີ |

> **QR ທີ່ລູກຄ້າສະແກນ ແມ່ນບັນຊີຂອງຄົນຂັບເອງ** — ຈັດການທີ່ **D43 · ບັນຊີຮັບເງິນ (QR)**
> ແອັບສ້າງ payload `laoqr://` ໃຫ້ອັດຕະໂນມັດ ພ້ອມໃສ່ຈຳນວນເງິນຂອງຖ້ຽວນັ້ນ

### ຄົນຂັບເພີ່ມ / ແກ້ໄຂ ເອງໄດ້ (D43 + D44)

**ມີໄດ້ຫຼາຍບັນຊີ** — ເລືອກອັນໃດເປັນ **“ບັນຊີຫຼັກ”** ທີ່ເອົາມາສ້າງ QR ຕອນຈົບຖ້ຽວ

| ເຮັດຫຍັງໄດ້ | ຢູ່ໃສ |
|---|---|
| ເພີ່ມບັນຊີໃໝ່ | ປຸ່ມ **+ ເພີ່ມບັນຊີຮັບເງິນ** (D43) |
| ແກ້ໄຂ | ກົດແຖວບັນຊີ ຫຼື ໄອຄອນ ✏️ |
| ຕັ້ງເປັນບັນຊີຫຼັກ | ໄອຄອນ ⭐ ໃນແຖວ |
| ລຶບ | ໄອຄອນ 🗑 (ຕ້ອງເຫຼືອຢ່າງໜ້ອຍ 1 ບັນຊີ) |
| ປິດຮັບຜ່ານ QR | ສະວິດ — ຈະຮັບແຕ່ເງິນສົດ ແລະ ກະເປົາ |

**2 ວິທີໃສ່ຂໍ້ມູນ (D44)**

1. **ພິມເອງ** — ມີ**ແປ້ນພິມໃນແອັບ** ໃຫ້ພິມໄດ້ຈິງ
   - ຊ່ອງເລກບັນຊີ → ແປ້ນຕົວເລກ, ກັ່ນຕອງແຕ່ຕົວເລກ, ຈັດກຸ່ມ 4 ຕົວອັດຕະໂນມັດ, ສູງສຸດ 20 ຕົວ
   - ຊ່ອງຊື່ → ແປ້ນ **ABC / ລາວ** ສະຫຼັບໄດ້, ຊື່ເຈົ້າຂອງບັນຊີແປງເປັນຕົວພິມໃຫຍ່ໃຫ້ເອງ
   - ມີປຸ່ມ ລ້າງທັງໝົດ · ລົບຕົວທ້າຍ · ຕົວນັບຕົວອັກສອນ
2. **ອັບໂຫຼດຮູບ QR** — ບັນທຶກຮູບ QR ຈາກແອັບທະນາຄານ ແລ້ວເລືອກມາ
   ລະບົບອ່ານ **ທະນາຄານ · ເລກບັນຊີ · ຊື່** ອອກໃຫ້ອັດຕະໂນມັດ

**ຕົວຢ່າງ QR ສົດ** ຢູ່ເທິງສຸດຂອງຟອມ — ພິມໄປ QR ປ່ຽນໄປ ເຫັນຜົນທັນທີ

**ກົດຄວາມປອດໄພ**: ປ່ຽນເລກບັນຊີ ຫຼື ຊື່ → ສະຖານະ `verified` ຖືກຣີເຊັດເປັນ **ລໍຢືນຢັນ** ໂດຍອັດຕະໂນມັດ

**ເງິນເຂົ້າກະເປົາໃນແອັບ ມີແຕ່ 3 ທາງ:**
1. ຖ້ຽວທີ່ລູກຄ້າເລືອກຈ່າຍ**ຜ່ານກະເປົາ**
2. ຄົນຂັບ**ເຕີມເງິນ**ເອງ (D30)
3. **ໂບນັດ**ຈາກບໍລິສັດ

ຢືນຢັນດ້ວຍການທົດສອບ: `collectPay` ດ້ວຍ `cash` ແລະ `qr` ບໍ່ເພີ່ມຍອດກະເປົາເລີຍ (`+0`),
ມີແຕ່ `wallet` ທີ່ເພີ່ມ (`+53,000`)

## ແທັບ “ເດໂມເຕັມຈໍ” 🖵

**ແອັບຈິງ ກົດໄດ້ ເຕັມຈໍ** — ບໍ່ມີ JSON, ບໍ່ມີ event log, ບໍ່ມີລາຍການໜ້າຈໍ
ເໝາະຕອນສາຍຕໍ່ຈໍ ຫຼື ຍື່ນຄອມໃຫ້ລູກຄ້າລອງກົດເອງ

| ປຸ່ມ | ເຮັດຫຍັງ |
|---|---|
| **⛶ ເຕັມຈໍ** | ເຂົ້າໂໝດເຕັມຈໍຂອງບຣາວເຊີ — ໂທລະສັບຂະຫຍາຍໃຫ້ໃຫຍ່ສຸດອັດຕະໂນມັດ |
| **💡 ຄຳໃບ້** | ເປີດ/ປິດແຖບບອກວ່າ “ກົດຫຍັງຕໍ່” ໃນໜ້ານັ້ນ |
| **⚡ ຂ້າມການລໍ** | ຂ້າມຕົວນັບຖອຍຫຼັງ (20 ວິ / 60 ວິ / ການເດີນທາງ) |
| **‹ ກັບຄືນ** | ຖອຍໜ້າ |
| **↻ ເລີ່ມໃໝ່** | ລ້າງທຸກຢ່າງ ກັບໄປໜ້າເປີດແອັບ |

ແຖບລຸ່ມ = **ກະໂດດໄປຈຸດສຳຄັນ** 15 ຈຸດ (ເປີດແອັບ · ລົງທະບຽນ · ໜ້າຫຼັກ · ງານເຂົ້າ · ປະມູນ ·
ໄປຮັບ · ແຊັດ · ເດີນທາງ · ຮັບເງິນ · ໃຫ້ຄະແນນ · ບັນຊີ QR · ກະເປົາ · ລາຍໄດ້) — ບໍ່ຕ້ອງກົດຜ່ານທຸກໜ້າ

ແຖບເທິງບອກ **ລະຫັດ ແລະ ຊື່ໜ້າຈໍປັດຈຸບັນ** (ເຊັ່ນ `D11 · ໜ້າຫຼັກ (ພັກ)`) ໄວ້ອ້າງອີງຕອນເວົ້າ

> **3 ແທັບນຳສະເໜີ ຕ່າງກັນແນວໃດ**
> · **ນຳສະເໜີ** = ສະໄລ້ໜ້າຈໍລ້ວນໆ ບໍ່ກົດໄດ້
> · **ວິທີໃຊ້ແອພ** = ໜ້າຈໍ + ຄຳອະທິບາຍເປັນຂັ້ນຕອນ
> · **ເດໂມເຕັມຈໍ** = ແອັບຈິງ **ກົດໄດ້** ເຕັມຈໍ

## ແທັບ “ວິທີໃຊ້ແອພ” 📖

ສຳລັບ**ນຳສະເໜີການນຳໃຊ້ແອັບ** ໃຫ້ຄົນທີ່ບໍ່ເຄີຍເຫັນມາກ່ອນ — ເລົ່າເປັນ **11 ຂັ້ນຕອນ**
ຕັ້ງແຕ່ລົງທະບຽນຈົນຮັບເງິນ ແຕ່ລະຂັ້ນມີ:

| ສ່ວນ | ເນື້ອໃນ |
|---|---|
| **ໜ້າຈໍຈິງ** | 1–3 ໜ້າຈໍຂອງຂັ້ນນັ້ນ — ກົດເພື່ອເປີດຂະໜາດເຕັມ |
| 👤 **ຄົນຂັບເຮັດ** | ລຳດັບສິ່ງທີ່ຄົນຂັບຕ້ອງກົດ / ໃສ່ |
| ⚡ **ລະບົບເຮັດ** | ສິ່ງທີ່ແອັບເຮັດໃຫ້ເບື້ອງຫຼັງ |
| 💡 **ຈຸດເດັ່ນ** | ສິ່ງທີ່ຄວນເນັ້ນຕອນນຳສະເໜີ |

**11 ຂັ້ນຕອນ:** ລົງທະບຽນ → ຢືນຢັນຕົວຕົນ → ເຂົ້າສູ່ລະບົບ → ເປີດຮັບງານ → ຮັບອໍເດີ →
ປະມູນລາຄາ → ໄປຮັບລູກຄ້າ → ສົ່ງລູກຄ້າ & ຮັບເງິນ → ໃຫ້ຄະແນນລູກຄ້າ → ຮັບເງິນ & ກະເປົາ → ລາຍໄດ້ & ຜົນງານ

ກົດ **ຕົວເລກ** ເພື່ອເບິ່ງເທື່ອລະຂັ້ນ (ດີສຳລັບສາຍຕໍ່ຈໍ) ຫຼື **“ທັງໝົດ”** ເພື່ອເລື່ອນອ່ານ

> ຕ່າງຈາກແທັບ **ນຳສະເໜີ** ຢູ່ບ່ອນ: ນຳສະເໜີ = ສະໄລ້ໜ້າຈໍລ້ວນໆ · ວິທີໃຊ້ແອພ = ມີຄຳອະທິບາຍປະກອບ

## ການນຳທາງ realtime (D17 · D19)

ນຳທາງຢູ່ໃນແອັບເລີຍ ບໍ່ຕ້ອງສະຫຼັບໄປ Google Maps — ແລະ **ເປັນຂອງຈິງ ບໍ່ແມ່ນຮູບຈຳລອງ**:

- **ເສັ້ນທາງຈິງຕາມຖະໜົນ** — ດຶງຈາກ OSRM (`steps=true`) ໄດ້ທັງເສັ້ນທາງ ແລະ ຄຳສັ່ງລ້ຽວ
  ພ້ອມ**ຊື່ຖະໜົນຈິງເປັນພາສາລາວ** (ເຊັ່ນ “ຖະໜົນໜອງບົວທອງ”, “ຖະໜົນ ເອຊຽນ”)
- **ລົດເຄື່ອນຕາມເສັ້ນທາງທຸກວິນາທີ** — ຄິດຕຳແໜ່ງດ້ວຍການ interpolate ຕາມໄລຍະສະສົມ
  ພ້ອມໝຸນລູກສອນຕາມທິດທາງ (bearing) ແລະ ແຜນທີ່ຕິດຕາມລົດອັດຕະໂນມັດ
- **ຄຳສັ່ງລ້ຽວອັບເດດສົດ** — “ອີກ 110 ແມັດ · ລ້ຽວຂວາ ເຂົ້າ ຖະໜົນ ໄກສອນ” ພ້ອມແຖບ “ຈາກນັ້ນ…”
- **ETA / ໄລຍະເຫຼືອ / ເວລາເຫຼືອ ນັບຖອຍຫຼັງສົດ** ແລະ ແຖບຄວາມຄືບໜ້າ
- **ສຽງແຈ້ງທາງ** — ແຈ້ງຄັ້ງດຽວຕໍ່ຄຳສັ່ງ ຕອນໃກ້ຈຸດລ້ຽວ (ປິດ/ເປີດໄດ້)
- **ປຸ່ມ ຕິດຕາມລົດ / ເບິ່ງທັງເສັ້ນທາງ / ສຽງ** ຢູ່ເທິງແຜນທີ່
- ບໍ່ມີເນັດ → ຫຼົບໄປໃຊ້ເສັ້ນທາງປະມານອັດຕະໂນມັດ (ບໍ່ພັງ)

### ເປັນຫຍັງຈຶ່ງລື່ນ

ເຄື່ອງຈັກນຳທາງ **ຂຽນໃສ່ DOM ໂດຍກົງ** (`navPaintUI` / `navPaintMap`) ບໍ່ໄດ້ render ໜ້າຈໍຄືນ —
ຖ້າ render ຄືນທຸກວິນາທີ ແຜນທີ່ Leaflet ຈະຖືກສ້າງໃໝ່ ແລະ ກະພິບ.
ຫຼັງກົດປຸ່ມໃດໜຶ່ງ (ໜ້າຈໍຖືກສ້າງຄືນ) `paintDemo()` ຈະຜູກແຜນທີ່ ແລະ ຂໍ້ຄວາມນຳທາງກັບຄືນໃຫ້ອັດຕະໂນມັດ.

| ສ່ວນ | ຢູ່ໃສ |
|---|---|
| ດຶງເສັ້ນທາງ + ຄຳສັ່ງລ້ຽວ | `routeNav()` ໃນ `js/ui.js` |
| ແປ maneuver → ພາສາລາວ | `instrText()` / `TURN_LO` / `turnIcon()` |
| ເລຂາຄະນິດ (ຕຳແໜ່ງ · ທິດທາງ) | `cumDist()` / `posAt()` / `bearingOf()` |
| ເຄື່ອງຈັກ | `navStart()` / `navStep()` / `navState()` / `navStop()` |
| ວາດໃສ່ແຜນທີ່ & DOM | `navBindMaps()` / `navPaintMap()` / `navPaintUI()` |
| ຜູກເຂົ້າໄຫຼງານ | `startNav()` / `navFor()` ໃນ `js/app.js` |

> ຕອນພັດທະນາຈິງ ປ່ຽນ `routeNav()` ໄປໃຊ້ Google Directions ຫຼື Mapbox Directions
> ແລະ ປ່ຽນການຈຳລອງຕຳແໜ່ງເປັນ GPS ຈິງ (`watchPosition`) — ໂຄງທີ່ເຫຼືອໃຊ້ໄດ້ຄືເກົ່າ.

## ແຊັດ realtime + ແປພາສາອັດຕະໂນມັດ (D20)

ລູກຄ້າຕ່າງປະເທດ (ຈີນ · ໄທ · ອັງກິດ) ເປັນເລື່ອງປົກກະຕິໃນລາວ — ແຊັດຈຶ່ງ**ແປໃຫ້ສອງທາງ**:

```
ຄົນຂັບພິມ:  ຂ້ອຍຮອດແລ້ວ ລໍຢູ່ໜ້າປະຕູ
ລູກຄ້າເຫັນ:  我到了，在门口等您        🇨🇳

ລູກຄ້າພິມ:  我马上出来 🙏
```

## ສິ່ງທີ່ເປັນ mock (ຕ້ອງປ່ຽນຕອນພັດທະນາຈິງ)

- **ຂໍ້ມູນ & API** — ຢູ່ໃນ `js/data.js` ບ່ອນດຽວ (ບໍ່ມີ backend ຈິງ)
- **ຢືນຢັນຕົວຕົນ (KYC)** — ຈຳລອງ · ຈິງຕ້ອງໃຊ້ບໍລິການ OCR ບັດ + face match
- **ແຜນທີ່** — OpenStreetMap + Leaflet (ຕ້ອງມີເນັດ) · ໂຫຼດບໍ່ໄດ້ຈະສະຫຼັບໄປແຜນທີ່ SVG ອັດຕະໂນມັດ
- **ຕຳແໜ່ງລົດ** — ຈຳລອງແລ່ນຕາມເສັ້ນທາງດ້ວຍຄວາມໄວຄົງທີ່ · ຈິງຕ້ອງໃຊ້ GPS (`watchPosition`)
- **ສຽງແຈ້ງທາງ** — ຂຶ້ນເປັນ toast · ຈິງຕ້ອງໃຊ້ TTS ພາສາລາວ
- **ຮູບຄົນ/ລົດ** — ພາບປະກອບ SVG (ວາງໄຟລ໌ໃນ `assets/` ໄດ້ຄືກັນກັບແອັບລູກຄ້າ)

## ຂໍ້ແນະນຳການພັດທະນາຈິງ

- Mobile: **Flutter ຫຼື React Native** — ຕ້ອງແລ່ນພື້ນຫຼັງ + GPS ຕໍ່ເນື່ອງຕະຫຼອດເວລາຮັບງານ
- **ຕ້ອງມີ foreground service** (Android) / background location (iOS) ບໍ່ດັ່ງນັ້ນ OS ຈະຂ້າແອັບ
- ນຳທາງ: Google Maps SDK ຫຼື Mapbox Navigation SDK
- KYC: OCR ບັດປະຈຳຕົວ + face match (Onfido / Sumsub / ຫຼື ລະບົບພາຍໃນ)
- Realtime: WebSocket `/ws/driver/{id}` (ງານໃໝ່ · ຜົນການປະມູນ) + `/ws/booking/{id}` (ສະຖານະຖ້ຽວ)
- Push: FCM ພ້ອມ **high-priority channel + ສຽງດັງແມ່ນເປີດໂໝດງຽບ** ສຳລັບງານໃໝ່
- Offline: ຕ້ອງ queue event ໄວ້ສົ່ງພາຍຫຼັງ ແລະ reconcile ຄ່າທຳນຽມຕອນເປີດແອັບໃໝ່
